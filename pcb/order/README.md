# Order lists

Generated by `make order` (`pcb/tools/order_bom.py`) from the boards' part tables: exactly the parts, no spares.
Parts a distributor does not carry are listed last in its file, marked "NOT AT DIGIKEY" / "NOT AT MOUSER" with the
other distributor's part number (at present Mouser lacks the WAGO 2604-3102, the Harwin P70-2200045 and the
ADAU7002); remove them before importing and order them from the other distributor. The battery-free edition's
parts go up with `make order-push VARIANT=na-plain` (or `eu-plain`, `both-plain`).

| File | Contents |
| --- | --- |
| `unit_na_digikey.csv`, `unit_na_mouser.csv` | One NA plate: wiring board, ring board, riser, back cover flex; spacer studs, standoffs, FFC |
| `unit_eu_digikey.csv`, `unit_eu_mouser.csv` | One EU plate: mains board, 5 V board, EU cap board, back cover flex; PE lever connector |
| `devkit_digikey.csv`, `devkit_mouser.csv` | The devkit: 5 NA and 5 EU plates (`make order DEVKIT_SETS=n`); its 5 PCBs of each design are in `pcbway/` |
| `pcbway/` | PCBWay packs for the devkit (5 PCBs of every design, 5 sets of parts per variant; ring board, EU cap board and cover flex as fit-test prototypes): option A (PCBWay fits the SMD parts) and option B (bare boards); see `pcbway/README.md` |

Rocker (D-97): both variants' lists take the E-Switch RA412C1100 (second source on the same footprint, D-88;
UL/cUL 16 A 125 VAC and 10 A 250 VAC, ENEC 10(4) A 250 V~; datasheet
https://configured-product-images.s3.amazonaws.com/Datasheets/RA4.pdf). Check its tab rows on the first part and
solder it after the board is screwed down. The Marquardt 1802.2504 (Mouser 979-1802.2504) stays the design's
reference part on the same footprint. With it, one plate of either variant comes from DigiKey alone.

## Importing

- DigiKey: myLists / BOM Manager, upload the `_digikey.csv` file and confirm the column mapping
  (Digi-Key Part Number, Manufacturer Part Number, Manufacturer, Quantity, Customer Reference). The
  DigiKey part number is the cut-tape packaging where the part comes on tape (`DIGIKEY` in
  `pcb/tools/order_bom.py`); with the MPN alone the import picks a full reel or rejects parts sold in
  several packagings.
- Mouser: BOM Import (Projects), upload the `_mouser.csv` file and confirm the column mapping
  (Mouser Part Number, Mfr Part Number, Manufacturer, Quantity, Customer Part Number). The Mouser part
  number is filled in where Mouser's import does not match the MPN (`MOUSER` in `pcb/tools/order_bom.py`).

## Live stock and upload (`make stock`, `make order-push`)

`pcb/tools/distributors.py` uses the distributors' APIs. Keys come from the environment only, never the repo:

| Variable | For |
| --- | --- |
| `DIGIKEY_CLIENT_ID`, `DIGIKEY_CLIENT_SECRET` | DigiKey Product Information v4 (an app at developer.digikey.com, client credentials): stock, status, lead time |
| `MOUSER_SEARCH_KEY` | Mouser Search API (My Mouser, APIs): stock, lifecycle, Mouser part numbers |
| `MOUSER_CART_KEY` | Mouser Cart API: the cart upload |
| `DIGIKEY_SITE`, `DIGIKEY_CURRENCY`, `MOUSER_COUNTRY`, `MOUSER_CURRENCY` | optional, default CA / CAD |

- `make stock` (also run by `make order` when keys are set): every part in the lists at both distributors (stock, status, lead time, distributor part number),
  written to `build/stock.md`. It fails when a part breaks the parts rule (D-84: active and in stock or normally
  stocked at one of them); "review" marks a part listed active with none in stock. A distributor without keys is
  skipped.
- `make order-push`: the parts for one plate by default, NA: `VARIANT=na|eu|both` (default `na`; `na-plain`,
  `eu-plain`, `both-plain` for the plain plates, D-109), `PLATES=n`
  (default 1; `both` = n of each), exactly what the plates use, as the CSVs. `PRIMARY=digikey` (default) or
  `mouser`: the primary distributor gets every part it carries, the other one the rest (the lines marked NOT AT … in the CSVs).
  Examples: `make order-push VARIANT=eu`, `make order-push PLATES=3`. The rockers as in the CSVs (D-97).
  With DigiKey keys set, each DigiKey line goes up to a price break where the larger quantity costs less in
  total (e.g. 8 at 1.20 = 9.60 against 10 at 0.864 = 8.64); a lower unit price that costs more in total is left
  alone. `--no-price-breaks` (`python3 pcb/tools/distributors.py push ...`) keeps the exact counts. DigiKey: the
  list goes to myLists' third-party endpoint (no key) and comes back as a single-use link that opens it as a
  cart or a myLists list. Mouser: a cart (Search key for the part numbers, Cart key for the cart); the cart key
  is printed, the cart is in My Mouser. `python3 pcb/tools/distributors.py push eu 1 --dry-run` shows the
  payloads without sending.

### Getting the keys

DigiKey (Product Information v4, client credentials; reads stock and status, cannot touch an account):

1. Sign in at https://developer.digikey.com/ with a DigiKey account.
2. Organizations (top of the page), Create Organization, give it a name, Add Organization.
3. In the organization: Production Apps, Create Production App, give it a name.
4. OAuth Callback: any https URL, e.g. `https://localhost:8139/digikey_callback` (the stock check signs in
   without it, the form needs one).
5. Tick Product Information V4, save.
6. View, Credentials, show key: copy the Client ID and Client Secret into `DIGIKEY_CLIENT_ID` and
   `DIGIKEY_CLIENT_SECRET`.

Mouser (two separate keys):

1. Sign in to My Mouser at https://www.mouser.com/ (create the account if needed).
2. My Account (personal information), APIs: request a Search API key (form). Mouser emails it: put it in
   `MOUSER_SEARCH_KEY`. It reads stock, lifecycle and Mouser part numbers.
3. On the same page, request the Order API key: Mouser uses it for the Cart API too. Put it in
   `MOUSER_CART_KEY`. **This key can place orders on the account**: keep it out of shared machines and
   containers that do not need it; the stock check does not.

Setting them: environment variables only, e.g. in `~/.bashrc` (or the shell's profile):

```bash
export DIGIKEY_CLIENT_ID='...'
export DIGIKEY_CLIENT_SECRET='...'
export MOUSER_SEARCH_KEY='...'
export MOUSER_CART_KEY='...'      # only where carts are built
```

In the devcontainer, pass them from the host instead of writing them into a file in the repo, e.g. in
`.devcontainer/devcontainer.json`: `"remoteEnv": {"MOUSER_SEARCH_KEY": "${localEnv:MOUSER_SEARCH_KEY}"}` (one line
per variable). Never commit a key; `make stock` and `make order-push` print no key.

## Quantities

Per-plate count times the plates, no spares: one plate, or the devkit's sets. `make order-push` with DigiKey keys
raises a line to a price break where that costs less in total; the CSVs stay exact. Stock: `make stock`.
